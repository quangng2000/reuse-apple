# Android RE-USE streaming (research)

This optional Android module runs the **stateful NVIDIA Real-time RE-USE** model,
with explicit per-layer temporal and convolution caches carried between hops.
It is **noncommercial research and education only under NSCLv1**. It is separate
from `reuse-audio-android` and its commercial 30-layer offline model. It must not
be added to the paid app without a separate commercial license.

```kotlin
implementation("io.github.quangng2000:reuse-streaming-android:0.1.3")
```

The API accepts finite mono 16 kHz FP32 PCM, uses a 640-sample Hann analysis
window and 320-sample hop, and supports exported exits 3–12 (default 4), with
zero lookahead. ONNX Runtime CPU execution is FP32; no FP16, quantization or
NNAPI provider is enabled. This is an incremental inference API, not a claim
that every Android device can sustain a 20 ms hop in real time. Benchmark your
chosen exit and thread count on target hardware.

```kotlin
// All calls block. Use one dedicated worker, never the microphone callback.
val receipt = StreamingModelManifest.read(trustedBundledManifest)
val enhancer = StreamingEnhancer(modelFile, receipt,
    StreamingEnhancerConfiguration(layers = receipt.layers, intraOpThreads = 2))
enhancer.use {
    it.warmUp() // optional; resets all disposable state afterward
    for (chunk in microphoneChunks) {
        writePcm(it.push(chunk))
    }
    writePcm(it.finish())
}
```

Supply any chunk sizes. The first output waits for 640 input samples. `finish()`
requires at least 640 samples, reflects the EOF tail and preserves the exact
total input sample count. It may be called once per stream; use `reset()` before
the next recording. `reset()` clears every cache, reflection buffer and overlap.
No automatic peak normalization or gain change is applied. Input validation
rejects nonfinite samples before changing state. An inference error or
cancellation requires reset. `StreamingCancellationToken.cancel()` interrupts
an active ONNX call and is checked between frames; time spent inside the
provider until it observes termination remains device dependent. `close()` waits
for the serialized active call, so cancel its token before closing from another
thread. Instance methods serialize concurrent calls, but callers should preserve
their intended chunk order with a single worker.

Model weights are downloaded/exported separately, never bundled into the AAR.
The receipt pins model SHA-256, size, checkpoint/source identity, exit depth,
sampling contract and every state tensor name/shape. Bundle the trusted export
receipt with your application; do not trust one fetched alongside downloaded
weights. The [model release](https://github.com/quangng2000/reuse-audio/releases/tag/android-streaming-models-v1) supplies fixed-depth ONNX files; use the matching trusted manifest from [`model/manifests/`](model/manifests/) in your app. Model and manifest SHA-256 pins are recorded in [`model/catalog.json`](model/catalog.json). See [`tools/streaming-export`](../../tools/streaming-export/) for reproducible exports and validation.

The native DSP library is `reusestreaming_dsp`, with all four standard Android
ABIs. Its pinned PocketFFT header and transform arithmetic are unchanged from the offline SDK.
The transform JNI adapter differs only in the JNI class symbol prefix; a separate
transport helper validates and clears persistent direct FP32 state buffers. Native code and all license
notices are included in the sources artifact. See `src/main/assets/reuse-streaming/licenses/`.

Host tests use the same native transform and actual ORT CPU runtime. To run the
optional real-model parity suite, provide `REUSE_STREAMING_MODEL_FILE`,
`REUSE_STREAMING_MODEL_MANIFEST`, and `REUSE_STREAMING_PARITY_DIR` generated by
the pinned exporter, then run `./gradlew :reuse-streaming:testReleaseUnitTest`.

## Experimental Vulkan: v2 only

Android 0.1.3 exposes `ExperimentalVulkanStreaming.create()` for the
measured eight-layer FP32 Vulkan v2 bundle. It selects the tiled matrix and
convolution kernels by default. `createTiled()` is a compatibility alias for
the same path. The ordinary `StreamingEnhancer` constructor still uses CPU
inference, and Apple APIs are unchanged.

The only accepted Vulkan bundle manifest SHA-256 is
`951adf47ebece2c27a5af4df22b91c30c8a442b8caa04bb01db102ceb0ac733a`.
The original v1 baseline and v3 candidate are rejected, even if their files are
otherwise intact. Supply the unchanged audited v2 bundle and currently pinned
ARM64 native library; neither is downloaded by the factory or bundled in the
Maven AAR, including version 0.1.3.

```kotlin
val enhancer = ExperimentalVulkanStreaming.create(
    bundleDirectory = auditedV2Bundle.absoluteFile,
    libraryFile = extractedVulkanLibrary.absoluteFile,
    configuration = StreamingEnhancerConfiguration(layers = 8, intraOpThreads = 1),
)
```

CPU thread count does not control Vulkan workgroups. All eight layers, FP32
weights, 31 state tensors and the streaming framing contract remain unchanged.
`createProfiled(..., tiled = true)` remains available for v2 diagnostics;
profiling timings must not be mixed with normal latency measurements.

In the recorded Galaxy S25 Ultra comparison, v2 averaged 17.69 ms versus
18.55 ms for v3; each had 4/320 calls above 20 ms. This is historical evidence
for the selection, not a new benchmark or an every-hop real-time guarantee.
The GPU path remains experimental and NSCLv1 noncommercial; its tested Adreno
subgroup behavior does not establish general Vulkan-device portability.

See [the Vulkan guide](../../tools/android-streaming-vulkan/README.md) for
artifact admission, state semantics and validation. Historical multi-bundle
comparison instrumentation is archived outside active source sets under
`android/benchmarks/streaming/archive/vulkan/`; use commit `ad4ceda` and its
matching fixtures to reproduce those experiments. The published 0.1.2 artifact
predates this Vulkan API; 0.1.3 adds the API, while the pinned GPU library and
model bundle remain separate from the AAR. The CPU-native experiments
below are separate from the Vulkan v2 bundle selection.

## Local experimental eight-layer frequency kernel

The local source checkout also exposes `ExperimentalNativeStreaming.create` for
the separately validated native frequency-scan experiment. It is explicit and is
not enabled by the ordinary `StreamingEnhancer` constructor or the published
0.1.2 artifact. It retains FP32 and the same weights, but permits the small
rounding differences checked by the native numerical validation. No model,
receipt, native binary or dependency is downloaded by this factory.

```kotlin
val enhancer = ExperimentalNativeStreaming.create(
    modelFile = experimentalModel,
    manifestFile = trustedExperimentalManifest,
    libraryFile = extractedNativeLibrary, // absolute path to libreuse_streaming_scan.so
    libraryReceiptFile = trustedNativeLibraryReceipt,
    configuration = StreamingEnhancerConfiguration(layers = 8, intraOpThreads = 4),
)
```

Bundle the trusted manifests/receipts with the application and package the exact
validated arm64-v8a `.so` in `jniLibs` with native library extraction enabled.
The factory checks the graph, original checkpoint, native source identity,
library ABI, compiler contract, file size and SHA-256 before registering custom
code. Other Android native ABIs are rejected for this experiment; the ordinary
constructor continues supporting its existing depths and four ABIs. A separately
pinned macOS host library is accepted for tests. The model remains NSCLv1
noncommercial research software. Set `REUSE_NATIVE_STREAMING_DIRECTORY` to the
validated generated native artifact folder, alongside the eight-layer parity
environment variables above, to run the additional host integration tests.

`ExperimentalNativeStreamingV2.create(...)` has the same explicit file/configuration
arguments for the separately pinned ABI2 frequency-plus-temporal experiment. It
requires its own graph, native library and trusted receipts; V1 remains available
with its original pins. Both variants retain all 31 temporal/convolution caches
and the complete finite-output check before each state commit. The ordinary
constructor selects neither experiment. To run V2 host comparisons against V1,
the released copying runtime and the independent numerical fixtures, also set
`REUSE_NATIVE_STREAMING_V2_DIRECTORY` to the V2 generated artifact directory.

`ExperimentalNativeStreamingInlineV2.create(...)` is a third explicit factory for
the separately pinned ARM64 inline exponential experiment. It keeps the validated
V1 and bulk V2 factories available and accepts only its own exact graph/library
and MLAS provenance receipts. Its native exponential uses the pinned ONNX Runtime
1.23.2 FP32 NEON algorithm; it enables neither FP16 nor fast-math. Set
`REUSE_NATIVE_STREAMING_INLINE_V2_DIRECTORY` alongside the V1/V2 host paths to run
its numerical, all-state, tail/reset and concurrent custom-registry tests.

`ExperimentalNativeStreamingStableV2.create(...)` separately pins the stable
Softplus experiment, including its Eigen provenance, while keeping every earlier
factory available. It evaluates the stable FP32 `max(x, 0) + log1p(exp(-abs(x)))`
form and preserves the selected original branch for extreme/nonfinite inputs.
Its numerical results may differ by FP32 rounding, so it remains explicit and
experimental. Set `REUSE_NATIVE_STREAMING_STABLE_V2_DIRECTORY` to include its
complete host comparisons; no finite-state checks are removed.
